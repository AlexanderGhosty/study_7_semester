# Статический анализатор C# — лабораторная работа №3

Консольное приложение для варианта 1 выполняет обратный анализ живых локальных
переменных. Оно обнаруживает инициализации и присваивания, результат которых не
считывается до следующей перезаписи или выхода из метода.

Анализатор строит синтаксические деревья, семантическую модель и графы потока
управления Roslyn только в памяти. Вызов `Emit` отсутствует, временная сборка
анализируемого кода не создаётся, сам код не запускается.

## Правило

`DFA3001_DeadLocalValue` срабатывает для определения локальной переменной `x`,
если `x` не входит в множество живых переменных непосредственно после этого
определения.

Поддерживаются:

- инициализаторы локальных переменных;
- простые присваивания `x = value`;
- составные присваивания `x += value`, `x -= value` и другие;
- операции `x++`, `x--`, `++x` и `--x`;
- аргументы `out x` как определения;
- аргументы `ref x` как чтения и последующие определения;
- чтения в выражениях, условиях, вызовах и `return`;
- слияние ветвей и обратные рёбра циклов через CFG.

Записи в параметры, поля, свойства и элементы массивов не относятся к правилу:
вариант ограничен локальными переменными обычных методов.

## Модель анализа

Для каждого базового блока `B` вычисляются множества `USE[B]`, `DEF[B]`,
`LiveIn[B]` и `LiveOut[B]`:

```text
LiveOut[B] = union LiveIn[S], S in successors(B)
LiveIn[B]  = USE[B] union (LiveOut[B] - DEF[B])
```

Блоки обходятся в обратном порядке до неподвижной точки. Затем операции каждого
достижимого блока просматриваются в обратном порядке. Объединение состояний
путей делает реализацию may-анализом: переменная считается живой, если её
значение может быть прочитано хотя бы на одном продолжении потока.

## Требования

- .NET 10 SDK;
- доступ к NuGet при первоначальном восстановлении
  `Microsoft.CodeAnalysis.CSharp` 4.11.0.

В методичке указан .NET 8/9. Для этой реализации пользователь явно разрешил
использовать установленный SDK 10.0.112 и целевую платформу `net10.0`.

## Сборка и запуск

Из каталога `code_analyze/l3`:

```bash
dotnet build src/CodeAnalyzer/CodeAnalyzer.csproj
dotnet run --project src/CodeAnalyzer/CodeAnalyzer.csproj -- samples/correct/Correct.cs
dotnet run --project src/CodeAnalyzer/CodeAnalyzer.csproj -- samples/defects/Defects.cs
dotnet run --project src/CodeAnalyzer/CodeAnalyzer.csproj -- samples/directory
```

Принимается ровно один аргумент: файл `.cs` или каталог. Каталог обходится
рекурсивно; `bin` и `obj` исключаются, а пути сортируются для стабильного вывода.

## Формат предупреждения

```text
Файл: samples/defects/Defects.cs
Строка: 9
Правило: DFA3001_DeadLocalValue
Сообщение: Значение локальной переменной 'overwritten', присвоенное в строке 9, не считывается до перезаписи или выхода из метода.
Рекомендация: Удалите ненужное присваивание либо используйте вычисленное значение; если правая часть имеет побочный эффект, сохраните сам вызов.
```

После всех диагностик печатается `Всего предупреждений: N`.

## Коды завершения

| Код | Значение |
|---:|---|
| `0` | предупреждений нет |
| `1` | найдено хотя бы одно мёртвое значение |
| `2` | ошибка аргументов, пути, чтения, синтаксиса или построения CFG |

## Проверка

```bash
./tests/verify.sh
```

Сценарий собирает проект и проверяет:

- корректный пример с ветвлением, составным присваиванием и циклом;
- пять дефектов: неиспользованный инициализатор, перезапись, последнее
  присваивание, неиспользованный результат `out` и мёртвый результат `++`;
- пограничный пример с may-слиянием, `ref`/`out`, строкой и комментарием;
- рекурсивный анализ каталога;
- отсутствующий путь, неверное расширение, пустой каталог и синтаксическую
  ошибку.

Фактический результат последнего запуска: сборка успешна, сценарий завершён
со строкой `All checks passed.`

## Ограничения

- Анализируются обычные методы с телом; конструкторы, аксессоры, лямбды и
  локальные функции не входят в текущий охват.
- Анализ внутрипроцедурный: эффект вызываемых методов, псевдонимы, указатели,
  `dynamic` и рефлексия не прослеживаются.
- May-слияние может скрыть значение, мёртвое лишь на части путей. Например, если
  переменная читается только в одной ветви `if`, её определение считается живым.
- Захват локальной переменной вложенной функцией не связывается с потоком
  внешнего метода и может приводить к ложному предупреждению.
- Предупреждение относится к неиспользованному результату присваивания, но не
  доказывает, что всю строку безопасно удалить: правая часть может иметь
  побочный эффект.
- Неполный набор исходников или отсутствующие зависимости могут ухудшить
  семантическое связывание. Если CFG построить невозможно, программа возвращает
  код `2`.
