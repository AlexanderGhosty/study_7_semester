# Статический анализатор C# — лабораторная работа №2

Консольное приложение для варианта 1 обнаруживает повторную модификацию
счётчика внутри тела цикла `for`. Анализатор читает исходный код и строит
синтаксическое дерево Roslyn, но не компилирует и не запускает проверяемую
программу.

## Правило

`SA2001_LoopCounterModifiedInBody` срабатывает, если переменная, объявленная и
изменяемая в заголовке `for`, напрямую изменяется и в теле этого цикла.

Поддерживаются:

- префиксные и постфиксные `++` и `--`;
- простое присваивание `i = ...`;
- составные присваивания `i += ...`, `i -= ...`, `i *= ...` и другие.

Изменение в секции итератора заголовка не является дефектом. Комментарии,
строковые литералы и доступ к одноимённому члену (`item.i++`) не создают
ложное предупреждение.

## Требования

- .NET 10 SDK;
- доступ к NuGet для первоначального восстановления
  `Microsoft.CodeAnalysis.CSharp`.

## Сборка и запуск

Из каталога `code_analyze/l2`:

```bash
dotnet build src/CodeAnalyzer/CodeAnalyzer.csproj
dotnet run --project src/CodeAnalyzer/CodeAnalyzer.csproj -- samples/correct/Correct.cs
dotnet run --project src/CodeAnalyzer/CodeAnalyzer.csproj -- samples/defects/Defects.cs
dotnet run --project src/CodeAnalyzer/CodeAnalyzer.csproj -- samples/directory
```

Аргументом может быть один файл `.cs` или каталог. Каталог просматривается
рекурсивно, а файлы анализируются в алфавитном порядке.

## Формат предупреждения

```text
Файл: samples/defects/Defects.cs
Строка: 9
Правило: SA2001_LoopCounterModifiedInBody
Сообщение: Счётчик 'i' цикла for, объявленного в строке 7, повторно изменяется в теле цикла.
Рекомендация: Удалите изменение счётчика из тела и оставьте управление шагом в секции итератора for.
```

Поле `Строка` указывает на некорректную модификацию, а сообщение содержит имя
счётчика и строку объявления цикла. После диагностик печатается
`Всего предупреждений: N`.

## Коды завершения

| Код | Значение |
|---:|---|
| `0` | предупреждений нет |
| `1` | найдено хотя бы одно предупреждение |
| `2` | ошибка аргументов, пути или чтения файлов |

## Проверка

```bash
./tests/verify.sh
```

Сценарий собирает проект и проверяет корректный пример, три вида прямой
модификации, многострочный цикл, вложенный блок, анализ каталога, пограничный
случай и ошибку входного пути.

## Структура

```text
src/CodeAnalyzer/   исходный код анализатора
samples/correct/    код без предупреждений
samples/defects/    целевые дефекты варианта 1
samples/corner/     известное ограничение анализа
samples/directory/  проверка обработки каталога
tests/verify.sh     воспроизводимая проверка
report.md           отчёт по лабораторной работе
PLAN.md             план выполнения
```

## Ограничения

Базовая версия анализирует переменные, объявленные непосредственно в заголовке
`for` и изменяемые в его секции итератора. Она не распознаёт изменение через
`ref`/`out`, вызов метода, указатель или пользовательский оператор. Для таких
случаев потребуются семантическая модель, анализ потоков данных и иногда
межпроцедурный анализ.

Обход намеренно не входит в тела локальных функций и лямбда-выражений:
одноимённый идентификатор там может обозначать другой символ, а отложенный код
не обязательно выполняется как непосредственный шаг текущей итерации.

Методичка указывает .NET 8/9, но для этой реализации по решению пользователя
выбраны установленный SDK 10.0.112 и целевая платформа `net10.0`.
