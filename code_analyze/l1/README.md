# Статический анализатор C# — лабораторная работа №1

Консольное приложение для варианта 1 проверяет оформление и именование в
исходных файлах C#. Анализатор только читает текст: он не компилирует и не
запускает проверяемый код.

## Реализованные правила

| Код | Проверка |
|---|---|
| `STYLE001` | длина строки не превышает 120 символов |
| `STYLE002` | строка не содержит табуляцию |
| `STYLE003` | непустая строка не заканчивается пробелами |
| `STYLE004` | пустая строка не содержит пробелы |
| `STYLE005` | имя класса начинается с прописной буквы |

Каждое нарушенное правило создаёт отдельное предупреждение. Для `STYLE003`
не проверяются полностью пустые строки с пробелами: их без дублирования
обрабатывает `STYLE004`.

## Требования

- .NET SDK 10;
- сторонние библиотеки не требуются.

## Сборка и запуск

Из каталога `code_analyze/l1`:

```bash
dotnet build src/CodeAnalyzer/CodeAnalyzer.csproj
dotnet run --project src/CodeAnalyzer/CodeAnalyzer.csproj -- samples/correct/Correct.cs
dotnet run --project src/CodeAnalyzer/CodeAnalyzer.csproj -- samples/directory
```

Аргументом может быть один файл `.cs` или каталог. Каталог просматривается
рекурсивно, найденные файлы анализируются в алфавитном порядке.

Формат предупреждения:

```text
Файл: samples/defects/Defects.cs
Строка: 3
Правило: STYLE005: имя класса
Сообщение: Имя класса 'userService' начинается не с прописной буквы.
Рекомендация: Переименовать класс так, чтобы его имя начиналось с прописной буквы.
```

После всех сообщений печатается строка `Всего предупреждений: N`.

## Коды завершения

| Код | Значение |
|---:|---|
| `0` | предупреждений нет |
| `1` | найдено хотя бы одно предупреждение |
| `2` | ошибка аргументов, пути или чтения файлов |

## Проверка

```bash
./tests/verify.sh
```

Сценарий собирает проект и проверяет корректный файл, файл с пятью видами
дефектов, каталог из нескольких файлов и несуществующий путь.

## Структура

```text
src/CodeAnalyzer/  исходный код анализатора
samples/correct/  пример без предупреждений
samples/defects/  пример, нарушающий все пять правил
samples/directory/ пример анализа каталога
tests/verify.sh   воспроизводимая проверка
report.md         отчёт по лабораторной работе
PLAN.md           план выполнения
```

## Ограничения

Анализ выполняется по строкам и регулярным выражением, а не по синтаксическому
дереву C#. Поэтому текст `class badName` внутри комментария или строкового
литерала может вызвать ложное предупреждение. Регулярное выражение также не
распознаёт все допустимые Unicode-идентификаторы C#. Для устранения этих
ограничений потребуется разбор исходного кода через Roslyn.
